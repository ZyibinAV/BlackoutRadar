# ADR-005 — PowerOutage Event Model

**Статус:** Accepted

**Дата:** 2026-08-08

**Версия:** 1.0

---

# Назначение

Зафиксировать архитектурное решение,
определяющее понятие отключения электроэнергии
в предметной области BlackoutRadar.

Документ определяет,
что считается одним событием отключения
и каким образом данное событие
представляется внутри системы.

---

# Контекст

Информация
об отключениях электроэнергии
поступает
из различных источников.

Одно опубликованное объявление
может содержать:

- один адрес;
- несколько адресов;
- одну трансформаторную подстанцию;
- несколько трансформаторных подстанций;
- единый временной интервал;
- общую причину отключения.

При проектировании модели
необходимо определить,
что является одной бизнес-сущностью.

---

# Проблема

Если каждое упоминание адреса
рассматривать
как отдельное отключение,

то информация:

- о причине;
- времени;
- источнике;

будет многократно дублироваться.

Если же отключение
рассматривать
как документ,

то возникают сложности
при обработке документов,
содержащих несколько независимых событий.

Необходимо определить
единую модель представления отключений.

---

# Рассмотренные варианты

## Вариант 1 — Одно отключение = один адрес

```
PowerOutage

↓

Address
```

### Преимущества

- простая модель;
- простые запросы.

### Недостатки

- дублирование данных;
- большое количество записей;
- невозможность представить
  единое событие.

---

## Вариант 2 — Одно отключение = один документ

```
Document

↓

PowerOutage
```

### Преимущества

- соответствует опубликованному источнику.

### Недостатки

- один документ
  может содержать
  несколько различных отключений;
- документ
  не является бизнес-сущностью.

---

## Вариант 3 — Одно отключение = одно событие

```
PowerOutage

↓

PowerOutageAddress
```

PowerOutage представляет
одно событие,
имеющее:

- единый временной интервал;
- общую причину;
- единый источник;
- список адресов.

### Преимущества

- отсутствие дублирования;
- соответствует предметной области;
- удобство сопоставления;
- удобство дедупликации.

### Недостатки

- необходимость отдельной связи
  с адресами.

---

# Принятое решение

PowerOutage представляет
одно событие отключения электроэнергии.

Одно событие
может затрагивать
произвольное количество адресов.

Адреса
связываются
с событием
через отдельную сущность.

---

# Архитектурные принципы

## 1. PowerOutage является бизнес-событием

PowerOutage
не является:

- документом;
- HTML-страницей;
- PDF;
- отдельным адресом.

PowerOutage
является событием предметной области.

---

## 2. Одно событие может содержать множество адресов

Адреса
не дублируют
общую информацию
об отключении.

---

## 3. Документ не является сущностью предметной области

Документ
рассматривается
только как источник информации.

После обработки
он не участвует
в бизнес-логике.

---

## 4. PowerOutage имеет жизненный цикл

Событие
может:

- появиться;
- измениться;
- быть отменено;
- завершиться.

Жизненный цикл
является частью предметной области.

---

## 5. История отключений сохраняется

После завершения события
оно не удаляется.

Исторические данные
могут использоваться
для анализа
и статистики.

---

## 6. Дедупликация выполняется отдельно

PowerOutage
не отвечает
за поиск дубликатов.

Данная ответственность
возлагается
на DuplicateResolver.

---

# Причины выбора

Выбранная модель:

- соответствует предметной области;
- минимизирует дублирование;
- облегчает сопоставление;
- облегчает поиск;
- поддерживает развитие системы.

---

# Положительные последствия

После принятия решения:

- уменьшается объем данных;
- упрощается Matching Engine;
- упрощается DuplicateResolver;
- сохраняется история событий;
- улучшается масштабируемость модели.

---

# Отрицательные последствия

Решение приводит к:

- появлению дополнительной сущности связи;
- увеличению количества JOIN;
- более сложной модели данных.

Данные недостатки признаны допустимыми.

---

# Влияние на реализацию

Настоящее решение оказывает влияние
на следующие компоненты:

- PowerOutage;
- PowerOutageAddress;
- DuplicateResolver;
- CandidateFinder;
- Matching Engine;
- Notification Engine.
