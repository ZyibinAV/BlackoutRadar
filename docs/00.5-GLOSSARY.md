# Глоссарий предметной области BlackoutRadar

## Назначение

Документ определяет единый словарь терминов
(Ubiquitous Language),
используемый в документации
и исходном коде проекта.

Все архитектурные решения,
модели данных, сервисы и алгоритмы
должны использовать определения,
приведенные в данном документе.

---

# Основные принципы

- Один термин — одно значение.
- Один объект предметной области — одно название.
- Не использовать синонимы для одной и той же сущности.
- Все новые термины должны добавляться в данный документ.
- Security-specific термины не считаются
  Business Domain Entities только потому,
  что используются системой.

---

# Термины

## User

Зарегистрированный пользователь системы,
получающий уведомления
об отключениях электроэнергии.

---

## Administrator

Пользователь с административными правами.

Имеет возможность:

- управлять пользователями;
- управлять источниками данных;
- управлять системой.

---

## Subscription

Подписка пользователя
на мониторинг конкретного адреса.

Подписка содержит:

- пользователя;
- адрес;
- период мониторинга;
- параметры проверки;
- настройки трансформаторной подстанции.

---

## Address

Каноническое представление адреса,
используемое системой
для хранения и сопоставления информации.

Адрес всегда хранится
в структурированном виде.

---

## Canonical Address

Нормализованный адрес,
используемый системой
как единственное представление.

Все операции:

- поиска;
- сопоставления;
- хранения

выполняются с использованием
канонического адреса.

---

## Region

Административный регион.

---

## Regional District

Административный район региона.

---

## City

Населенный пункт.

Принадлежит одному Region.

---

## City District

Район города.

Принадлежит одному City.

---

## Street

Улица внутри города.

Принадлежит одному City.

Street не принадлежит City District.

---

## House

Value Object,
представляющий номер дома.

Содержит:

- houseNumber;
- houseAddition;
- canonicalHouse.

---

## Transformer Station

Трансформаторная подстанция,
связанная с Subscription.

Используется в дальнейшем
для уточнения сопоставления
отключений с подписками.

---

## Source

Источник информации
об отключениях электроэнергии.

---

## Outage Provider

Компонент,
получающий данные
об отключениях из внешнего источника.

Outage Provider является
инфраструктурной ответственностью.

---

## Parsed Outage

Нормализованное представление
отключения после parsing
внешнего источника.

Parsed Outage используется
в Outage Processing Pipeline.

---

## Power Outage

Доменное событие
отключения электроэнергии.

Power Outage является
центральным объектом
Outage Processing Pipeline.

---

## Candidate

Временный результат
поиска потенциальных совпадений
для Power Outage.

Candidate не является
самостоятельным persisted
Business Domain Entity.

---

## Match

Результат Matching Engine,
представляющий сопоставление
Power Outage с Subscription.

---

## Notification

Доменный объект,
представляющий необходимость
уведомить пользователя
о найденном совпадении.

---

## Authentication

Процесс подтверждения
личности пользователя.

Authentication является
Security concern.

Authentication не определяет
права пользователя.

---

## Authorization

Процесс определения,
какие действия доступны
аутентифицированному пользователю.

Authorization является
Security concern.

---

## Access Token

Краткоживущий security credential,
используемый для доступа
к защищенным API.

Access Token не является
Business Domain Entity.

---

## JWT

JSON Web Token,
используемый в проекте
как формат Access Token.

JWT является
Security representation.

JWT не является
Business Domain Entity.

---

## Refresh Token

Security credential,
используемый для получения
нового Access Token
без повторной аутентификации.

Refresh Token:

- является Security concept;
- не является Domain Entity;
- имеет собственный Security lifecycle;
- может быть отозван;
- может участвовать в rotation;
- хранится в защищенном виде
  в persistence storage.

Refresh Token не является
частью Business Domain Model.

---

## OAuth2 Client

Security component,
используемый для аутентификации
через внешний OAuth2 Provider.

В проекте используется
GitHub OAuth2.

---

## Security Context

Контекст безопасности,
содержащий информацию
об аутентифицированном пользователе
для выполнения защищенного запроса.

Security Context относится
к Security Layer.

---

## Password Hash

Криптографическое представление
пароля пользователя,
используемое для безопасного хранения.

Исходный пароль
не хранится в системе.

---

## Token Hash

Защищенное persistence representation
Refresh Token.

Token Hash:

- хранится вместо исходного токена;
- не является Domain State;
- не является raw Refresh Token;
- используется Security/Persistence layer.

---

## Token Rotation

Security mechanism,
при котором существующий
Refresh Token заменяется
новым credential.

Rotation используется
для уменьшения риска
повторного использования
скомпрометированного токена.

---

## Revocation

Принудительное признание
Security credential недействительным
до истечения его естественного срока.

Revocation применяется,
в частности,
к Refresh Token.

---

## Security Phase

Этап проекта,
на котором реализуются:

- Authentication;
- JWT;
- Access Token;
- Refresh Token;
- Authorization;
- OAuth2;
- Security Hardening.
