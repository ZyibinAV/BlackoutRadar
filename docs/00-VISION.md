# BlackoutRadar

## Назначение

BlackoutRadar — это система мониторинга плановых отключений
электроэнергии, которая автоматически собирает информацию
из различных источников, сопоставляет ее с адресами,
интересующими пользователей, и отправляет уведомления
по выбранным каналам связи.

---

## Цель проекта

Создать современное backend-приложение,
демонстрирующее проектирование сложной бизнес-логики,
а не только CRUD-операций.

Проект ориентирован на практическое применение
и должен легко расширяться новыми источниками данных,
новыми способами уведомлений
и дополнительными алгоритмами сопоставления.

---

## Основные возможности

• регистрация пользователей

• управление адресами

• подписки на отключения

• автоматический мониторинг сайтов

• получение данных из различных источников

• нормализация адресов

• интеллектуальное сопоставление отключений

• уведомление пользователей

• управление источниками данных

---

## Основные принципы проекта

1. Domain First

Бизнес-логика важнее инфраструктуры.

---

2. Clean Architecture

Предметная область
не зависит
от Spring
или PostgreSQL.

---

3. Single Responsibility

Каждый сервис
решает только одну задачу.

---

4. Open/Closed Principle

Добавление нового источника данных
не должно требовать изменения существующей логики.

---

5. Replaceable Infrastructure

Любой внешний компонент
может быть заменен
без изменения доменной модели.

---

6. Canonical Data

Все адреса
хранятся
только
в нормализованном виде.

---

7. Event Processing

Система рассматривает отключение
как событие,
которое проходит несколько стадий обработки.

---

## Что НЕ является целью проекта

Проект не предназначен для:

• создания собственной поисковой системы;

• разработки универсального HTML-парсера;

• построения распределенной микросервисной архитектуры;

• обработки миллионов событий в режиме реального времени.

---

## Целевая архитектура

Monolithic Modular Application

Layered Architecture

Domain Driven Design (Light)

Adapter Pattern

Strategy Pattern

Factory Pattern

---

## Дальнейшее развитие

После завершения первой версии
архитектура должна позволять добавить:

• Telegram

• Push

• REST API

• мобильное приложение

• новые источники данных

• аналитику

• карту отключений

без изменения ядра системы.
